# @emsenn/relating-experimental

Relating, greenfielded as one coherent boundary system.

The category of relating is built from the `Mark → Utterance → articulate` base
upward. Every package operation is registered exactly once as an **action** — a
boundary morphism that is categorically a cocone leg injecting that operation into
the package's call surface. From a single `induceBins(module)` arrow, the coproduct
apex of those actions is projected to CLI, OpenAPI, MCP, and web UX as functorial
images of one carrier.

- **One dispatcher, four transports.** A single `relate` binary
  (`node:util.parseArgs`) reads stdin once, decodes by the argv-selected codec,
  runs the pure morphism, encodes, and writes stdout. `relate-serve` binds the
  *same* actions to `node:http`, projecting the one `induceBins` apex to CLI,
  **OpenAPI** (`GET /openapi.json`), **MCP** (`POST /mcp`), and **web UX**
  (`GET /` index, `GET /:verb` form, `POST /:verb`) as functorial images — no
  second ontology. Every HTTP/MCP/form POST runs through `dispatch`, so it is
  witnessed as EAVT exactly like a CLI call.
- **The full MCP knowledge-vault surface, from the one apex.** The `/mcp`
  projection serves all three standard MCP primitives as functorial images of the
  same `induceBins` carrier: **tools** (`tools/list`, `tools/call`) run the
  morphisms; **resources** (`resources/list`, `resources/read`) serve what the
  package already declares — each action's input/output JSON Schema and the live
  discovery carrier, auto-derived, plus any `resource()` a package registers
  (e.g. an `object.schema.json`); **prompts** (`prompts/list`, `prompts/get`)
  serve a guided template auto-derived from every action (`actionPrompt`) plus any
  composed flow a package registers with `prompt()`. An action is a cocone leg
  injecting a morphism; a `resource` injects an addressable artifact; a `prompt`
  injects a composed message template — the same apex, three projections.
- **Two formats, never one.** The wire is unforced — plain string for the
  articulation family, JSON between scripts, selectable by argv. EAVT is the shape
  of the **log**, not the wire.
- **Self-witnessing.** Every invocation reached through the scripting boundary
  (never a direct in-process call) is witnessed as an EAVT row — E=caller,
  A=morphism+arguments, V=return, T=timestamp — appended best-effort to a
  term-addressed dated log and settling into Datoms. The append-only log is the
  event-sourced write-model; the projected state is the read-model.
- **Objects are data.** Each category's object lives in an `object.schema.json`
  that is at once runtime validator, transport documentation, and the source of a
  TypeScript type generated by the forgetful functor `realize: Sub(J) →
  StructuralTypes` (`allOf`→`&`, `anyOf`/`oneOf`→`|`, properties→labeled products,
  `$ref`→named fixpoints; refinements forgotten into the schema as residual law).

Use the package `exports` map and source JSDoc as the normative API. The export map
is the categorical surface; codecs are representation boundaries, not ontology.
