# 2026-06-15

## Addendum: The Package Is Relating Now

The package name moved from `@emsenn/relationality` to `@emsenn/relating`.
That is not meant as a coat of paint.
"Relating" names the category we are trying to implement: a base object `Mark`, a base carrier `Utterance = (Token, Claim)`, and a base morphism `articulate`.

I also started a migration note at `dev/docs/explanations/category-of-relating.md`.
The point of that document is to stop treating `algebra`, `topology`, `logic`, `geometry`, and `analysis` as software buckets.
The target allocation follows the mathematical pressure the code has been revealing: current algebra wants to become topology, current topology wants to split toward logic and geometry, and current geometry wants to become analysis.
Symbols should move only when their domain, codomain, and normalization path back to Mark/Utterance/articulate are clear.

The first nested surface is now on disk:

```text
articulating/
  predicating/
    positing/
      settling/
```

Those files are barrels over the older implementation modules for now.
That is intentional.
The package can expose the mathematically correct containment chain before every implementation file has been moved, and tests can keep the old and new surfaces honest during the migration.

I also wrote down the general packaging rule set at `dev/docs/guides/category-theoretic-node-packaging.md`.
The short version: packages name categories, modules name objects or subcategories, nesting means mathematical containment, functions are morphisms, boundary modules are not ontology, and file moves require domain/codomain evidence.

That guide now also states the free-data discipline explicitly: core code must not introduce arbitrary JavaScript data as mathematical structure; codecs are the only free-data gates; public classes are carriers; public morphisms must normalize back to the base object and base morphism; and for this package that normal form is `Mark -> Utterance -> articulate`.

The test suite has a direct no-free-data regression at the base surface: articulating and predicating must carry an opaque Mark payload without reading, enumerating, or otherwise inspecting it.
If core code treats that payload as ordinary JavaScript data, the test throws.

## Relating, Pipes, and the Shape of a Mark

There is an old Unix feeling I keep wanting from `@emsenn/relating`: a program prints something another program can read, and the interesting part is not the plumbing.
You should be able to run a command, pipe its result into a read, feed that read back into a relation, and not stop every six inches to invent another local object protocol.

That is the practical software pressure behind the current package cleanup.
Shell users want pipes.
HTTP/OpenAPI users want request and response bodies that chain.
MCP users want tool results that can become tool inputs.
TypeScript users want the same callable shape without spawning a process.
Those are not four API designs.
They are four transports asking for the same morphism.

The first shape I moved the package toward was:

```text
boundary resource -> carrier/read resource
```

The token and claim arrive at a boundary as documents.
The relational core sees Marks, Tokens, Claims, Utterances, predication carriers, and settled readings.
The default wire form is EAVT/Datom JSONL because it is simple enough for shell composition and structured enough for API and MCP adapters.
Later work generalized the script boundary: package bins now read one declared JSON resource and write one declared JSON resource, including unary reads over `SettlementFiltration`.

An EAVT row may be spelled as a tuple:

```json
["token", "attribute", "value", "time"]
```

or as an object:

```json
{"e": "token", "a": "attribute", "v": "value", "t": "time"}
```

At the boundary this becomes an utterance whose token is `e` and whose claim is the richer record `{a,v,t}`.
A settled read emits EAVT again, but the value slot is no longer pretending to be a plain object coordinate:

```json
["subject", "predicate", {"object": "object", "charge": "potential"}, "time"]
```

That little nested value is doing real work.
It says: this is not just an asserted coordinate; this is a read, a settlement, something derived by the relational descent.
If a caller asks for Datom, the fifth slot carries that reading.

The executable may stamp time when the user does not supply one.
That is its job as a process at the I/O boundary.
The importable library code still does not get to read the clock behind your back.

## The One Arbitrary Thing

The package drifted in a familiar TypeScript way: useful code slowly forgot where arbitrary data was allowed to live.

In this mathematics, `Mark` is the arbitrary carrier.
A Mark may wrap anything.
That is the point, not an inconvenience to normalize away.
The core must not open arbitrary Mark payloads and decide that they are JSON, strings, records, subjects, predicates, objects, or anything else.
It may carry them.
It may articulate them.
It may induce relational structure around them.
It may not secretly install JavaScript's value theory as the package's ontology.

So the rule is now explicit:

- `Mark` is arbitrary.
- Tokens and Claims carry Marks.
- An Utterance is the admission shape, `(Token, Claim)`.
- Subject, predicate, object, and charge are derived readings.
- Representation boundaries may inspect payloads only to prove that the chosen representation can carry them.

This means old conveniences had to go.
There is no public Mark equality helper that compares arbitrary payloads.
Token and claim identity remain carrier judgments, but we do not decide the equality of all possible Mark contents by accidentally calling into JavaScript.

It also means JSON is not the Mark carrier.
JSON is a boundary carrier.
HTML is a boundary carrier.
TOML and Turtle are boundary carriers.
EAVT is a boundary carrier.
A Mark can be serialized through one of those only after the boundary has proved that this particular payload inhabits that representation.

## Frege Is Hiding in the Pipes

The categorical part matters here because otherwise this all looks like ordinary CLI cleanup.

Admission is not "declare subject, predicate, object."
Admission is an utterance.
Predicating happens after articulation.
The predication category opens a value-free cell set, the Fregean unsaturated place where the predicate has not been collapsed into a data field.
Charge is later, at positing and settling.
That is why directly injecting charge, polarity, denial, or a subject-predicate-object declaration into core is the wrong move.

The research corpus says the same thing in its own language: the predicating category carries the value-free cell set, `Phi = E x Pi x E`, and a cellular fiber.
Values enter later.
The code should make that invariant hard to violate.

The command line is not an ad hoc mini-app.
It is a POSIX pipe view over the same morphisms exposed by the TypeScript package.

## The Script Surface

The package-root `scripts/` directory now holds the executable wrappers.

`BoundaryDocument` is a deliberately plain name.
In TypeScript it is a string, but this is not a claim that Marks are strings.
It means the executable, HTTP adapter, MCP adapter, or caller has decoded a POSIX/API/MCP byte stream into a runtime document.
It is boundary material, not ontology.

The script surface is still separate from the ordinary package root.
The root is the normal Node package API: it rolls up public carrier constructors, carrier types, readers, and morphisms from the module indexes below it.
The `scripts` subpath is the callable script-morphism surface for shell/API/MCP adapters.

Consumers should not need obsolete internal paths to get ordinary relating capabilities:

```ts
import { mark, utterance, induce } from "@emsenn/relating";
import { parseLines, toEavt } from "@emsenn/relating/codecs/path/object/attribute/file/flatfile/serialization/json/jsonl/eavt";
```

The split is:

- root import: ordinary public relating API;
- `scripts` import: pure boundary-document script morphisms;
- nested subpath imports: deliberate dependence on a module boundary.

That keeps relating a mathematical library while preserving the over-the-wire script constraint as its own surface.

## Witnesses, Not Casts

Most of the code cleanup has been one pattern repeated at different scales: remove "trust me" assertions and replace them with witnesses.

Raw `JSON.parse` now belongs inside the JSON resource codec.
After parsing, the package proves a value is a `JsonValue`.
JSON objects are plain string-keyed records, not arbitrary JavaScript instances that happen to have enumerable properties.
The JSON codec now exports `JsonRecord` and `isJsonRecord`, and script/evaluate/datom code uses that shared witness instead of local record guesses.

Finite vocabularies are witnessed too.
`--order`, `--bound`, `--charge`, and wire charge readings are no longer cast from strings into mathematical names.
They pass through small parsers that know the finite carrier.
A malformed charge like `"maybe"` fails at the boundary instead of becoming an impossible member of Belnap's FOUR through TypeScript optimism.

The same cleanup touched the utterance log decoder.
A JSON value is not already an utterance log.
It becomes one only after the `meme-topology.utteranceLog` shape is witnessed and each encoded `(token, claim)` entry is present.

TOML got its own version of this: dotted table traversal now uses helper witnesses for tables and arrays of tables instead of mutating through asserted shapes.

Even stdin had a tiny version of the problem.
The shell helper no longer says `chunk as Buffer`; it constructs bytes from the chunk Node actually gives it.
Small thing, same principle.

## HTML and Other Boundary Manners

The HTML projector had a classic JavaScript leak: object-valued witness marks could render as `[object Object]`.
That is not a representation; it is an accident.

Object and array values now render through canonical JSON when they are HTML-projectable.
Opaque witness marks still fail before projection.
Packet identity canonicalizes frontier terms deterministically, so object key order does not leak into identity.

The EAVT/Datom codec follows the same rule.
Object-spelled EAVT rows must carry all four coordinates.
A row missing `t` or `v` is not a partial witness; it is not an EAVT.
Writing EAVT from a charged cell emits one row per present-side witness and refuses a non-JSON time witness instead of casting arbitrary Marks.

Again: the core can carry arbitrary Marks.
The boundary cannot lie about what it can serialize.

## What Changed in the Public Story

The public story is now easier to explain:

```sh
articulate-utterance
predicate-articulation-cell
posit-predication-site
settle-posit-presheaf
```

The scripts own stdin/stdout, then call `articulate()`, `predicate()`, `posit()`, and `settle()` directly.

The export map still matters.
It is not being collapsed into "just scripts."
The exported algebra, topology, logic, geometry, analysis, holography, and codec subpaths should name real carrier surfaces: domains, codomains, extrema, apex objects, morphisms, and representation boundaries.
The audit is not done, but the criterion is now written down.

## Topology Does Not Own JSON

I moved the log JSON codec out of topology and away from codec format paths, and later removed that script-level log codec entirely.

This was a small file move with a large meaning.
A topology carrier should not teach the package what JSON is.
JSON is a representation boundary: it may witness that a Mark payload can be carried through a JSON document, reject payloads that cannot inhabit that representation, and rebuild fresh Mark carriers on the other side.
It must not become ontology.

That wording matters.
Rebuilding a carrier from JSON is not mark equality.
It is a new admission about a prior wire witness, and the current package no longer exposes a dedicated log persistence script.

## Ordinal Closure Does Not Render Marks

The same boundary problem showed up in ordinal closure.
The topology engine had a `showOrdinal` helper that rendered a limit ordinal by reading `ordinal.label.mark.value`, and the same module imported the exact-number codec to move back and forth between native counts and carrier naturals.

I removed that display helper from topology.
If some caller needs a string for an ordinal, that belongs in a codec or display boundary, not in the closure engine.

I also changed the canonical omega labels from display strings such as `"omega*2"` and `"omega^2"` into carrier labels wrapped by Marks.
The closure search still has its internal bounded horizon, but the construction no longer imports `fromCount` or `toCount` from the codec layer, and it iterates over Natural members directly instead of decoding a native count.

The regression now checks that canonical omega labels are not strings.
The point is not that strings can never be marks; the point is that topology must not sneak display text in as the ontology of ordinal labels.

## Substitution Dynamics Counts as Topology

I made the same cut in `topology/substitution-dynamics`.
That module was importing the exact-number codec only to turn bounded native counts into `Natural` ranks and search bounds.
The algorithm still has finite matrix dimensions because the current matrix carrier is array-backed, but topology no longer calls the codec to manufacture its own mathematical naturals.

The primitive-matrix search now builds its bounded `Natural` internally by successor iteration, and the colimit module rank is counted carrier-natively over the relevant matrix suffix.
This is not the final word on matrix carriers, but it removes one more route where a core construction depended on a representation boundary.

The public topology barrel had the same smell: it was re-exporting `toCount`, `fromCount`, `toNumber`, `toInt`, and `fromInt` from the codecs package.
I removed that shortcut.
Topology can expose exact-number carrier types because those are mathematical carriers; the JS-number doors belong to `codecs`.

## Correction: Numeric Morphisms Are Not the Leak

I made one overbroad pass while chasing the free-data problem and then rolled it back.

The mistake was treating every native-number-shaped call as if it were automatically arbitrary JavaScript data leaking into the ontology.
That is not right.
`fromInt`, `fromRatio`, and friends are not random house-style conveniences.
They are named admission morphisms into exact-number carriers.
When `latticeSite(1, 2)` constructs a site by applying `fromInt`, or `orderingFraction` presents an exact rational through `fromRatio`, the important question is not "did a JavaScript number appear?"
The important question is "is this a lawful morphism with a real domain and codomain?"

So `geometry/cut-and-project` keeps its numeric-coordinate constructor surface, and `geometry/temporal` keeps using `fromRatio` for the exact ordering fraction.
The bad thing is not a boundary notation that admits integers or ratios.
The bad thing is core relational code inspecting arbitrary Marks, deciding their contents by JavaScript equality or display coercion, or letting JSON/CLI/HTML transport forms pretend to be ontology.

This is the sharper rule I should have used from the beginning:

- lawful admission morphisms are part of the mathematics;
- representation boundaries may inspect payloads to witness membership;
- core relational morphisms may carry Marks but must not compare or decode arbitrary Mark payloads;
- transport forms are witnesses, not category objects.

## Algebra Is Not a Public Surface

I also made the first export-map cut that follows from the packaging rules as practice, not as manifest decoration.

`./algebra` was still public, but it did not name a real object or subcategory in the category of relating.
Utterance carriers, predication cells, bilattice charge, exact numbers, graded values, and carrier coincidence do not form one public object merely because they can share an internal source barrel.
Public exports have to say the actual domain, codomain, closure role, read role, or representation boundary.

So the package no longer exports `@emsenn/relating/algebra`.
The source barrel still exists for internal imports.
Public base admission lives at `@emsenn/relating/articulating`; predication lives at `@emsenn/relating/articulating/predicating`; value entry lives at `@emsenn/relating/articulating/predicating/positing`; settlement lives at `@emsenn/relating/articulating/predicating/positing/settling`.

That is the right kind of rule enforcement here: not a new JSON object in `package.json` explaining what should be true, but one fewer false public path.

## Conservation Gets Its Own Analysis Path

The other side of the same rule is positive: when a public surface really does name a contained object or morphism family, the path should show the containment.

`analysis/conservation` is the boundary operator and conservation-law surface over oriented relation flows.
It was already public through `import { conservation } from "@emsenn/relating/analysis"`, but the package did not expose `@emsenn/relating/analysis/conservation`.
That flattened a real subobject into a convenience namespace.

The package now exports `./analysis/conservation`, matching `./analysis/differential`.
The public path is justified by the conservation tests themselves: the boundary operator detects conserved flows, leaks, completion witnesses, and obstructions.

## Geometry Belongs Under Its Carrier

The same containment rule applies to geometry, but the carrier matters more than the word "geometry."
Spatial geometry is read from the predication base, so it is public at `./articulating/predicating/geometry/spatial`.
Temporal geometry is read from settlement, so it is public at `./articulating/predicating/positing/settling/geometry/temporal`.

There is no public `./geometry` bucket now.
A consumer should see the morphism chain that generates the geometry it imports.

## Exact Numbers Cross at Their Own Codec

The exact-number codec is another real boundary.
It is the place where carrier numbers cross to and from native JavaScript numbers and decimal strings: `fromInt`, `fromRatio`, `toNumber`, `parseDecimal`, `toDecimalString`, and the matrix helpers live there because they witness that crossing.

That boundary used to be reachable only through `./codecs`.
The package now exports `./codecs/exact-number` directly, matching the rule that contained representation boundaries should have their own import paths when they are public commitments.

## Logic and Geometry Move Under Their Generating Morphisms

The better rule is stronger than "split topic buckets."
A logic or geometry surface belongs under the morphism whose codomain carries it.

So typed theory is public at `./articulating/predicating/typed-theory`, because it is consequence over predication base objects.
Spatial geometry is public at `./articulating/predicating/geometry/spatial`, because space is read from the predication base.
Bilattice linear logic is public at `./articulating/predicating/positing/logic`, because it is the value logic used where charge enters predication.
Temporal geometry is public at `./articulating/predicating/positing/settling/geometry/temporal`, because time is the settling itself.

The bucketed paths `./logic`, `./logic/bilattice-linear-logic`, `./logic/typed-theory`, `./geometry`, `./geometry/spatial`, and `./geometry/temporal` are not package exports.

## Substitution Is Dynamics, Not Arithmetic

The package had a public `./topology/arithmetic` export whose own comment said it exposed substitution dynamics.
That name was doing topic-bucket work instead of category work.

The public surface is now `./topology/dynamics/substitution`.
It exports the substitution morphism family: rules, carriers, orbits, abelianization, gauge labelings, induced permutations, primitive-matrix witnesses, and colimit structure.
It does not re-export the exact rational helpers that the old `arithmetic` barrel included.
Native number crossing belongs at the `./codecs/exact-number` boundary.

## Analysis Reads Need Laws, Not Doorways

The `./analysis` barrel was already carrying several real read surfaces: evidence distributions, relation-graph Laplacians, spectral polynomial reads, conservation laws, and differential readings.
Conservation and differential already had explicit paths; evidence, Laplacian, and spectral did not.

Those are not helper functions hiding inside analysis.
They are downstream projection surfaces over settled carriers, so the package now exports `./analysis/evidence`, `./analysis/laplacian`, and `./analysis/spectral` directly.
The combined `./analysis` surface can still stand for the analysis subcategory, but consumers no longer have to treat it as a namespace bag to reach the contained reads.

The important point is not that each file got a public doorway.
That would be a fake criterion: renaming the strings would still make the same kind of test pass.
The justification has to live in the actual read laws already tested in the analysis modules: evidence distributions are exact histograms, Laplacians derive relation-graph spectra from sections, and spectral reads return witness/obstruction judgments over exact number carriers.

I also removed the package export-map string-list test.
It was not a theorem about the category.
It only compared one set of strings with another set of strings, and replacing those strings with nonsense would not change the shape of the test.
Export-map audits still matter, but they need evidence from the symbols' domains, codomains, laws, and containment, not just a manifest checklist.

## Evidence Bits Move to the Boundary

The next actual code cut was in `analysis/evidence`.
That module owns exact charge histograms, evidence coordinates, absolute-continuity obstructions, mixedness judgments, independence judgments, distortion reads, and screening-off judgments.
Those are analysis objects and morphisms over exact carriers.

But the same module also exported entropy, KL divergence, and mutual information as JavaScript `number` bit figures.
The comments already admitted what they were: boundary reads.
So I moved those functions to `codecs/evidence`.
Analysis no longer imports `toNumber` from the codec layer just to produce floats.
The codec boundary imports the exact evidence carriers and reads them into native numbers when a caller explicitly asks for bit figures.

That is the packaging rule in code: exact analysis stays analysis; lossy float projection crosses at a representation boundary.

## Spectral Polynomials Stop Owning Native Arrays

The same boundary was present in `analysis/spectral`.
The spectral module was exporting `polyFromInts` and `polyToInts`, which cross between JavaScript `number[]` values and exact integer-polynomial carriers.
Those helpers are useful, but they are not spectral laws.
They are representation gates.

So `analysis/spectral` now exposes `integerPolynomial` as the carrier constructor over exact `Integer` coefficients, while `codecs/spectral` owns `polyFromInts` and `polyToInts`.
The spectral core also stopped importing `fromCount` and `toCount` from codecs for its finite Routh/root-location loops; it now constructs and reads loop counts through local successor/predecessor walks over `Natural`.

This leaves the analysis surface about exact polynomial judgments: reciprocity, resultants, root-location witnesses/obstructions, Pisot judgments, dominant-root convergence, Mahler measure, and matrix-Pisot reads.
Native integer arrays are now explicitly a boundary notation.

## Still Open

There is still a lot to do.

The export map needs a term-by-term categorical audit.
If a subpath names a domain, codomain, extremum, apex, morphism, or representation boundary, it can stay public.
If it is merely convenient implementation furniture, it should not be in the public map.

There are also subject/predicate/object names in codecs and readings.
Some are correct because they are derived readings at a boundary.
Others may be false primitive admissions.
Those need to be checked against the predication category, not against taste.

Downstream, the same discipline needs to reach the web package, agents, games, and computers: no free JavaScript data sneaking in as relation; no bad injections; no transport format pretending to be ontology.

For now the package is closer to the shape I want: arbitrary data enters as a Mark, functions converge toward morphisms over token and optional claim, EAVT is the default pipeable boundary, and the root import no longer gives TypeScript users a private shortcut around the script surface.
